# ADR-002: MFA/TOTP Library — Speakeasy

- **Status:** Accepted
- **Date:** 2026-08-03
- **Deciders:** Project stakeholder (via Authentication module review)

## Context

`09_SECURITY_GUIDELINES.md` AUTHN-004 mandates MFA (TOTP), available to all tenant users and **mandatory** for any Administrator-level Role or Platform Operator account. `02_TECH_STACK.md` (frozen, v1.1) has no TOTP library in its dependency list — this is a genuine gap between a binding security rule and the frozen tech stack, flagged in the Authentication Module Specification (`engineering/prompts/02_platform/00_auth.md` §13). Per CLAUDE.md §3/§14, introducing a new package requires an ADR before implementation.

## Options Considered

1. **Speakeasy** (`speakeasy` npm package) — mature, widely used TOTP/HOTP library; generates provisioning URIs (for QR codes) and verifies time-window-tolerant TOTP codes.
2. **otplib** — comparable modern alternative, more actively maintained upstream at time of writing, similar API shape.
3. **Roll a custom TOTP implementation** — rejected without extended discussion: RFC 6238 TOTP has subtle timing/encoding pitfalls; reimplementing cryptographic primitives is explicitly against this handbook's general engineering philosophy (`05_CODING_STANDARDS.md` Ch.2) of not reinventing well-solved, security-sensitive primitives.

## Decision

**Speakeasy**, per explicit direction. It becomes an approved addition to `02_TECH_STACK.md`'s Authentication section (added below, alongside JWT/Refresh Token/Passport.js/Argon2).

## Consequences

- `02_TECH_STACK.md` is updated to list Speakeasy under Backend → Authentication (done, this ADR).
- `apps/api/package.json` will need `speakeasy` (and its `@types/speakeasy` dev dependency) added at implementation time — tracked against this ADR, not a silent, unreviewed dependency add.
- MFA secrets (`Speakeasy`-generated) are sensitive data requiring encryption at rest (`03_ARCHITECTURE.md` §20.4) — the Authentication module's `user_credentials` table stores the secret encrypted, never in plaintext.
- QR-code provisioning (frontend MFA enrollment screen, `engineering/prompts/02_platform/00_auth.md` §18) renders the URI Speakeasy generates; no separate QR-generation library is implied by this decision alone — that remains a frontend implementation detail (likely a small QR-rendering component, evaluated at Frontend Planning, Ch.10 of `12_MODULE_DEVELOPMENT_GUIDE.md`).
