# Frontend Checklist

**Purpose:** Reusable checklist applied when writing or reviewing UI/client-side code.

**When it should be used:** During self-review before opening a PR, and during formal reviews logged in [../reviews/frontend/](../reviews/frontend/).

---

- [ ] UI matches intended design/UX for the feature
- [ ] Loading, empty, and error states are handled
- [ ] Forms validate input and show clear error messages
- [ ] No console errors or warnings in normal use
- [ ] Accessibility basics covered (labels, keyboard navigation, contrast)
- [ ] Responsive across expected viewport sizes
- [ ] No sensitive data exposed in client-side code or network payloads unnecessarily
- [ ] Component/state logic tested where non-trivial
